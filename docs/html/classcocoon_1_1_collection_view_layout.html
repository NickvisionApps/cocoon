Detailed Description

C++ handle for the Objective-C class NSCollectionViewLayout (AppKit).

Handles are cheap, copyable wrappers around a retained native object: copies refer to the same underlying instance.

◆ layout_attributes_for_drop_target_at_point()

CollectionViewLayoutAttributes cocoon::CollectionViewLayout::layout_attributes_for_drop_target_at_point ( const Point & point_in_collection_view) const

Calls -[NSCollectionViewLayout layoutAttributesForDropTargetAtPoint:].

Returns an NSCollectionViewLayoutAttributes instance that identifies an appropriate proposed drop target from the given hover point. If the point is between items, the returned layout attributes may describe an inter-item gap, which is distinguished by having a representedElementCategory of NSCollectionElementCategoryInterItemGap, and a representedElementKind of NSCollectionElementKindInterItemGapIndicator. Its "frame" provides a bounding box for the gap, that will be used to position and size a drop target indicator, and its "indexPath" identifies the proposed "insert before" position. The frame might not contain the given point, if the insertion indicator should lie elsewhere. (For example, when a vertical Flow layout hit-tests a gap between rows, it may suggest an insertion gap to the left of the lower row's first item.) Subclasses should override this method to return appropriate results based on their knowledge of the particular layout. This method should return nil if no suitable drop target can be inferred from the given point.

◆ layout_attributes_for_elements_in_rect()

std::vector< CollectionViewLayoutAttributes > cocoon::CollectionViewLayout::layout_attributes_for_elements_in_rect ( const Rect & rect) const

Calls -[NSCollectionViewLayout layoutAttributesForElementsInRect:].

NSCollectionView calls these four methods to determine the layout information. Implement -layoutAttributesForElementsInRect: to return layout attributes for for supplementary or decoration views, or to perform layout in an as-needed-on-screen fashion. Additionally, all layout subclasses should implement -layoutAttributesForItemAtIndexPath: to return layout attributes instances on demand for specific index paths. If the layout supports any supplementary or decoration view types, it should also implement the respective atIndexPath: methods for those types. During a batch update (-[NSCollectionView performBatchUpdates:completionHandler:], or a diffable data source's -applySnapshot:animatingDifferences:completion:), -layoutAttributesForItemAtIndexPath: must return non-nil attributes for every item that still exists after the update. Returning nil for such an item is a programming error and will raise an assertion. This normally means the layout's backing data (for example a section provider) or the data source's contents were changed out of step with the update; apply those changes as part of the update rather than before it.

◆ layout_attributes_for_inter_item_gap_before_index_path()

CollectionViewLayoutAttributes cocoon::CollectionViewLayout::layout_attributes_for_inter_item_gap_before_index_path ( const IndexPath & index_path) const

Calls -[NSCollectionViewLayout layoutAttributesForInterItemGapBeforeIndexPath:].

Returns an NSCollectionViewLayoutAttributes instance that describes the inter-item gap preceding the given item indexPath. You may pass an indexPath whose "item" index equals the number of items in the section, to request a description of the gap after the last item. The result has a representedElementCategory of NSCollectionElementCategoryInterItemGap, and a representedElementKind of NSCollectionElementKindInterItemGapIndicator. Subclasses should override this method to return appropriate results based on their knowledge of the particular layout.
