Detailed Description

C++ handle for the Objective-C class NSExtensionContext (Foundation).

The host app context from which an app extension is invoked. When a host app sends a request to an app extension, it provides an extension context. For many app extensions, the most important part of the context is the data the user wants to work with, which is contained in the ''inputItems'' property. Handles are cheap, copyable wrappers around a retained native object: copies refer to the same underlying instance.

Example
#include <cocoon.h>
cocoon::ExtensionContext extension_context;

void cocoon::ExtensionContext::cancel_request_with_error ( const Error & error) const

Calls -[NSExtensionContext cancelRequestWithError:].

Signals the host to cancel the app extension request, with the supplied error, which should be non-nil. The @c userInfo of the @c NSError will contain a key @c NSExtensionItemsAndErrorsKey which will have as its value a dictionary of @c NSExtensionItems and associated @c NSError instances.

◆ complete_request_returning_items()

void cocoon::ExtensionContext::complete_request_returning_items ( const std::vector< Object > & items,
std::function< void(bool)> completion_handler ) const

Calls -[NSExtensionContext completeRequestReturningItems:completionHandler:].

Signals the host to complete the app extension request with the supplied result items. The completion handler optionally contains any work which the extension may need to perform after the request has been completed, as a background-priority task. The @c expired parameter will be @c YES if the system decides to prematurely terminate a previous non-expiration invocation of the completion handler. Calling this method will eventually dismiss the associated view controller.
